# Otty — notes for Claude

- Target is macOS, but development may happen on Windows. `npm run typecheck` and `npm run build` work anywhere. Capture, permissions and Reminders only work on macOS (`process.platform === 'darwin'` guards).
- Electron 45 has an **async, W3C-style clipboard API** (`clipboard.read/readText/write/writeText` return Promises, plus `ClipboardItem`). The old sync `readHTML`/`readImage` APIs are gone.
- Electron 45 no longer downloads its binary on install; the `postinstall: install-electron` script does it, so electron-vite can find `node_modules/electron/path.txt`. Don't remove it.
- The tool loop is `src/main/loop.ts`, shared by chat turns and jobs. `ToolContext.allowed` is enforced first thing in `runTool`, and Claude's web search needs `ChatRequest.serverSearch`, so an allowed list is a real limit. The loop, `tools/` and `JobRunner` never import electron (D-45, `noElectron.test.ts`): settings reach the Mac through the `SettingsBackend` that `core.ts` plugs in (`settingsOnMac.ts`, whose `macKeychain` is the one place secrets are locked), and tools reach it through `ToolContext.mac` (`macHands.ts`), which only a chat turn gets.
- The main process owns the conversation history (`ChatSession` in `src/main/llm.ts`). The renderer only receives `ChatEvent`s. The API key never reaches the renderer.
- Model services live behind `Provider` in `src/main/providers/`, with one adapter per API format (OpenAI's, Anthropic's), not per company. Code outside it never builds a request or checks which service it is. Claude-only request fields stay in `claudeExtras`, because other Anthropic-style servers could reject them. `Message` keeps OpenAI's shape, and adapters translate as they send, so saved chats never change. Features read the `Profile` (`providers/profiles.ts`). With `web: 'off'` nothing may leave the Mac, and a local model never gets the saved key. Every request leaves through `send` in `net.ts` (D-52), which refuses anything off the Mac while `web` is `off`: never call `fetch` elsewhere in main, and give an SDK client `fetch: send`.
- Chats are saved as threads through the `ChatStore` interface in `src/main/store/`, backed by SQLite (`otty.db`, `node:sqlite`, synchronous on main; text only, images stripped by `store/images.ts`). `ChatSession` writes the question on send and only the turn's rows at its end (`write(thread, from)`). The schema is in `store/db.ts`: once released, change it with a new migration, never by editing one. Old message shapes are read through `store/upgrade.ts`. Matching rules live in `src/shared/match.ts` (also used by find-in-chat, `lib/findInChat.ts`), ranking in `store/search.ts`, and every backend must pass `store/__tests__/search.contract.ts`. Reopening one emits a `load` event. Each capture carries the frontmost app (`frontmostApp()` in `capture.ts`) as `AppInfo`; a message has `captures[]` (rules in `src/shared/captures.ts`).
- DeepSeek's cache needs each request to repeat the last one byte for byte, so `systemPrompt` depends only on settings. Anything per-turn goes in `turnNote` (`language.ts`), at the end of the user message, and nothing already sent is rewritten. `llm.test.ts` guards this.
- Explain terms are markdown links `[term](#explain)`, tips are `> 💡` blockquotes, and proofread answers carry a ` ```fixed ` block. All are rendered in `src/renderer/src/panel/Markdown.tsx`. Keep `prompts.ts` in sync if you change a format. Explain cards are cached in main (`explainCache.ts`), never in a renderer. Background calls (explain cards, titles) use `complete()` with `reasoning: 'least'` and never touch `ChatSession` history.
- Web safety: answers never load remote images (`Markdown.tsx`), built pages have a CSP (`electron.vite.config.ts`, build only), and `read_page` asks first unless `knownUrls.ts` finds the exact address in what the user sent or a search or page returned. Never count the model's own text, and keep tool messages from echoing model input as addresses. Reading pages from the Mac (`pageReader.ts`) only opens public addresses, checked in the lookup the connection itself uses (`publicLookup`, so DNS rebinding can't slip past), and checks each redirect, and Claude's `web_fetch` stays off because it would skip these checks. Copied HTML (`copyFormats.ts`) drops pictures and unsafe links, because Word fetches them on paste.
- UX for non-technical users comes first: friendly copy, no raw errors, and confirm cards for side-effecting tools.
- CI (`.github/workflows/ci.yml`, macOS) runs `npm ci`, typecheck, `npm test` and build on every PR. Keep `package-lock.json` committed and in sync.
- Docs: requirements `docs/REQUIREMENTS.md` · plan, roadmap and smoke test `docs/DEVLOG.md` · shipped work `docs/CHANGELOG.md` · ideas `docs/BRAINSTORM.md` · long-run direction `docs/AUTONOMY.md` · what's missing before a beta or paid release `docs/LAUNCH_READINESS.md` · UI design (names, layout, motion, micro-interactions, and the polish bar every screen spec must meet) `docs/DESIGN.md`, with the interactive draft in `docs/design/`.
- Otty is heading from reactive to proactive: long work runs as saved jobs, inputs become events, and the conversation never blocks. Check new features and architecture against the checklist in `docs/AUTONOMY.md`. Outside text can never choose what Otty does, and safety limits live in code, not prompts. The relationship with the otter comes first, and trust is Otty's ceiling, so a new level of reach ships only with its undo, visibility and attack tests.
- Estimates are effort, never time: size plans and ideas S/M/L by the amount and complexity of the work (the DEVLOG's scale), and never write days, weeks or hours as an estimate anywhere in the docs.
- Keep the docs moving: plan a feature as a DEVLOG entry before building it. When it ships, summarise it in CHANGELOG, delete the entry, add its smoke-test steps (each with a spec tagged `@step-N`, or a ✋ and the reason a person must check it; `tools/smoke/__tests__/coverage.test.ts` enforces it), and mark it `shipped` in BRAINSTORM. Add any feature or UX ideas you notice along the way to BRAINSTORM.
- Attachments (`src/main/files/`): the renderer only gets ids, names and thumbnails, never paths or file contents. Documents are read in a utility process (`fileWorker.js`, a second main entry in `electron.vite.config.ts`); `pdfjs-dist` and `mammoth` are runtime `dependencies` (externalized, loaded with `import()`), unlike everything else. Code files are the `code` kind (`files/languages.ts`) and are sent with line numbers; notebooks are read by cell (`files/notebook.ts`). Every text, code and notebook file goes through `maskSecrets` (`shared/secrets.ts`) in the worker, so a secret never reaches main, the model or `otty.db`; a new text-like kind must too. Highlights and typed words are masked as `ChatSession.send` takes them (`hideKeys`; typed words lose key shapes only), and `read_page` results in `tools/web.ts`. The lines something was hidden in, each value cut to `hint()`, stay in main's memory only (`hiddenLines.ts`, D-40).
- Hotkeys (highlight / snip / whole screen) open the small **quick view** at the cursor (`src/renderer/src/quick/Quick.tsx`); the floating bubble opens the full panel. Both render the conversation from main's `ChatEvent`s through `useChat` (`lib/useChat.ts`), so ↵ "continue in chat" just swaps windows. The panel is a frame plus screens (`renderer/src/frame/`, D-64): the window's width alone sets the layout through the bands in `frame/bands.ts`, and a screen never measures the window, so don't build views that only work in one narrow column.
- Window states (D-65, `src/main/roomy.ts`): one panel window, floating or roomy. Expand shows the Dock icon before the move and Shrink hides it after (W14); while roomy, whatever would open the floating window brings it forward; each state's bounds are main's alone (`windowBounds`, not `SETTABLE`). The app menu shows keys the window handles without registering them (`registerAccelerator: false`), and smoke fakes `app.dock`.
- UI work: `tools/ui-preview` (launch config `ui-preview`) renders the real views in a browser with a mock `window.otty`. Use `?view=panel|quick|pickup|viewer` and `&scene=chat|compose|empty|tray|settings|provider|page|proofread|memory|memories|math|code|drawing|chart|cap|near|steps|logbook|logbook-wait|-next|-sent|-changed|-noted|-empty|-running|-paused|-entry|-search|-none|typography|paused|frame-menu|frame-pushed|frame-rail|frame-medium|frame-wide|frame-min|home|home-quiet|home-first|home-running|home-paused|history|find|onboarding`, the cards `confirm-read|confirm-open|confirm-search|confirm-reminder|confirm-unusual|receipts|rewind|noted`, the answer states `thinking|stopped|failed-key|failed-long` and Settings' `settings-you|-keys|-privacy|-usage|-conn|-help|-find|-retention|-broken|-recording` (for `pickup`: `reading|nowords|failed`; for `viewer`: `picture|slides`) (`&home=none` hides the home-language features). Design tokens (colours and text roles, hairlines, elevation, radius, spacing `--s-*`, type `--fs-*`/`--lh-*`, icons `--i-*`, motion `--t-*`) are at the top of `styles.css`, from DESIGN.md's "Foundations". Reuse them instead of new hex values, sizes or borders: `rules/renderer.test.ts` fails on a font-size, weight, padding, gap or radius that isn't a token (a short off-scale list, each a written spec) and on text under 4.5:1 in either theme. `npm run screens` compares every scene, light and dark, with `tools/ui-preview/screens/baseline/`; a wanted change is `npm run screens:update` (it copies the screenshots CI took on the branch, since CI's Mac is the reference), in a PR of its own.
- Pick up text: `tools/otty-ocr/` is a Swift helper (Apple Vision), run by `src/main/ocr.ts` with the picture on stdin. `npm run dev` and `build:mac` build it into `build/bin`, and electron-builder ships it from there. Keep Chinese first in its language list. `pickup/Pickup.tsx` lays invisible text over the picture and handles ⌘C and ⌘A itself.
- Otty is painted art: frames in `src/renderer/src/assets/otty/` are generated from `tools/otty-art/source/` by `tools/otty-art/prepare.py` (cut-out, crop, blink frame). The app icon, `build/icon.icns`, comes from the same script and is committed so CI can use it. Don't hand-edit the WebPs or the icon; add a source and rerun the script. New sources are painted by `tools/otty-art/generate.py` (D-71, OpenAI key from the Keychain, `idle.webp` as the style reference), reviewed by eye against idle, and kept from its tries (ignored by git); every non-idle source is cut as a bust frame, except `cove-*`, which is split at its horizon into shore and water layers in `assets/cove/`, `float*` (the full-body Otty on its back), lined up with `float.webp` and cut whole, and the cove's pieces (`reeds*`, `stones`, `lilypad*`, `cloud*`; clouds are white on black), each cut to its own box in `assets/cove/`. `components/Otter.tsx` shows one frame per face (the bubble's moods, D-38, are its own: sleepy, hungry, munch, caught) and CSS moves them, stepped.
- UI icons are Flaticon UIcons (rounded set) via `components/Icon.tsx` — no emoji in UI chrome. Colours are tokens at the top of `styles.css`.
- Idle budget (NFR-3): under 0.5% of a core, measured with `OTTY_METRICS=1` (`metrics.ts`). A smooth `infinite` animation on an always-visible window redraws all day and cost 1.6% on its own, so step it or run it briefly, and re-measure after changing what runs while idle. Hidden windows get `data-asleep`, which pauses their animations. Measure and run long test jobs under `caffeinate`, because a sleeping Mac stalls timers and fails tests that wait on them.
- Whole-screen capture uses `desktopCapturer`, which throws when Screen Recording is off, so it needs a `needs-screen` path. Otty's windows go invisible during it (`withWindowsHidden`).
- Logs and diagnostics (D-50): main's `console.warn` and `console.error` are teed into otty.log in ~/Library/Logs/Otty by `src/main/log.ts`, masked, without the home path and cut short, so log facts and errors, never chats, highlights, files, answers or request bodies. Copy diagnostics (`src/main/diagnostics.ts`) is shown in full before it's copied and never names a key or a custom address. Keys come only from the Keychain: no plain-text fallback, and `DEEPSEEK_API_KEY` only when `!app.isPackaged` (D-51). The packaged app's fuses are in `electron-builder.yml` (D-49); never fork with `ELECTRON_RUN_AS_NODE`, use a `utilityProcess`.
- Services live in `src/shared/services.ts` (presets, privacy lines, `serviceAt`); `ConnectionFields.tsx` is the picker in Settings and onboarding. Keys are saved per service in `settings.ts`.
- The proofread card's marks come from `shared/diff.ts` comparing the highlighted text with the model's ` ```fixed ` block, never from the model.
- Memory (`src/main/memory/`): `remember` and `forget` have no confirm card, because the Noted line and its Undo are the control. `guard.ts` decides what may be kept, and never trusts the model's word: `told` comes from the user's typed words, and on any turn with a capture, file or web result a memory must rest on what they typed. What Otty knows goes in that turn's note (never the system prompt). Habits only store counts, and memory failures must never break an answer (`safely` in `llm.ts`).
- Math: `src/shared/math.ts` picks the tier and stays free of mathjs, which loads lazily in `src/main/math.ts` behind an allowlist of node types and functions. Add a function to the allowlist only if it's bounded. Only `$$…$$` is math (`Markdown.tsx`), so prices stay text.
- Try again and Edit (D-36, `ChatSession.rewind`): only the latest turn, never while it runs. The history is cut to a prefix and Try again resends the stored question message unchanged, so the cache holds (`rewind.test.ts`). An answer records what it can take back (`memories`, `jobs` by the id the chat chose) and what it can't (`lasting`), and `rewindPlan` lists both before anything goes.
- IPC (D-44): every channel is in `CHANNELS` (`src/main/ipc/check.ts`) with the views that may use it and a guard per argument; register with its `handle` or `on`, never `ipcMain` directly (`rules/ipc.test.ts`). Send ids, and let main look up what they are. `index.ts` is only the lifecycle (D-45): add to `core.ts`, `ipc/`, `captureRoute.ts`, `controls.ts` or `notify.ts`, and reach settings, stores and the provider from `ChatSession` through `SessionDeps`.
- Turns belong to chats: `ChatSession` keeps `live` turns by thread id, and only the chat on show reaches the windows (`tell`). Moving away never stops an answer; a new question in the same chat does.
- Jobs (`src/main/jobs/`): the truth is in `JobStore`, one row per history message, never in a promise. Only `JobRunner` changes a job's status, through `change()`, which saves first and refuses a move not in `jobs/states.ts`; steps are written in order through one chain per job. A job sees only its brief, and its tools are `JOB_TOOLS`, which stay read-only; a changing tool would be claimed once per call (`JobStore.claim`). The brief is the model's own text, so it never counts as knowing an address (`seedUrls` does). A confirm in a job throws `ToolPause`, and the unanswered call reruns on resume. `Supervisor` can only end tools early, never widen a limit. Friendly copy never says "job" or "queue".
- Tool safety: `src/main/toolSafety.ts` is the one table of what each tool reads, brings in, sends out and changes. `CHAT_TOOLS`, `OUTSIDE_TOOLS`, `JOB_TOOLS` and `LASTING_TOOLS` come from it, `ToolContext.allowed` is required, a test fails for a tool without a row, and `ruleOfTwo` runs when a job is built. Add a tool's row before its code. A tool is then one entry in `TOOLS` (`src/main/tools/index.ts`, keyed by those names, so neither compiles without the other): its definition and `offer(setup)` (null when not offered), its chip, its ledger `undo` and `run`. Add new entries at the end of their group: the order is part of every request, and DeepSeek's cache needs it to repeat. Read string arguments with `text()`. Inside a run, `RunTaint` tracks private data and outside words: once both are there, `search_web` shows its query on a card and Claude's own search goes off (`needsCard`, D-41).
- Scheduled jobs (`schedule_job`, D-27): the same read-only job with a `dueAt`, always behind a card. `JobRunner` sets one timer for the soonest due job (no polling), promotes due jobs once on wake or launch, and asks first when more than a day late. **Pause everything** (`settings.workPaused`, saved) stops answers and jobs and starts nothing until it's undone; `workPausedUntil` ends it by itself through `checkPause` in `controls.ts` (one timer, rechecked on launch and wake; D-39). Launch at login is a setting macOS owns (`app.setLoginItemSettings`), only in the installed app.
- Used (D-24): `forPrompt` returns `matched`, the memories that matched the question or app, and the answer keeps `used` (at most two). Being sent isn't being used.
- Smoke harness (D-47, `tools/smoke/`, not shipped; the `smoke` skill says how to run and extend it): `npm run smoke` (builds, then runs, under a machine-wide lock) drives the release build in `out/` with Playwright. `tools/smoke/app/` loads it hermetically (own home, mock keychain, sockets only to the fake world, a short list of real processes) and fakes the Mac through `require('electron')`, `execFile`, `fetch`, DNS and `Date`, so `src/` has no test hooks: keep it that way. Specs are `*.smoke.ts`, tagged `@step-N` from the checklist. Never widen the guard to make a test pass; `check-release.mjs` keeps smoke code out of `out/`.
- Eval (`tools/eval/`, not shipped): `npm run eval` needs `OTTY_EVAL_KEY` and runs real-model cases through the real loop and prompts, with network and Mac-changing tools stubbed. Add a case for every real failure or attack. Its scorers are tested in `npm test`. The committed baseline is in `tools/eval/baselines/`; compare a new run against it after changing a prompt, a hint or the model. Per-turn hints (`main/hints.ts`) go in the turn's note, never the system prompt; each names the weakness it works around, and the harness adds the same ones. Cases run four at a time, so per-case state (the scripted page and search) lives in `inScene` (`AsyncLocalStorage`), never a module variable.
- Drawings (D-30): ` ```mermaid `, ` ```svg ` and ` ```slides ` blocks become cards (`renderer/src/draw/`, loaded lazily). A drawing is only ever shown as a `data:` picture or our own escaped slide HTML in a shadow root; SVG goes through `sanitize.ts`, Mermaid runs strict after `cleanMermaid`. Exports are made in `main/draw.ts`'s hidden window (no JavaScript, every non-`data:` request cancelled), and main accepts only what `validExport` allows. Inside slides, diagrams use `~~~mermaid`. Keep `prompts.ts` in sync with `shared/slides.ts`. The CSP lives in `csp.config.ts`; `ui-preview-csp` builds the preview with it, to check something works under the real policy.
- Action ledger (D-46, `src/main/ledger.ts`): `runTool` writes a row through `begin` before any tool whose row in `toolSafety.ts` changes something, and step cards write one in `runStep`; an outcome says how to undo it (`undo: { ref, label }`). Try again's plan reads the ledger, falling back to the answer's fields for older chats. Rows hold masked plain words, live and die with chats, and `begin` never throws.
- Logbook (D-63, `src/main/logbook/`): one read-only query over jobs, the sent log and the ledger, with every word from `main/logbook/words.ts`; the renderer sends ids back (Undo through `ChatSession.undoChange`, notes through `JobRunner.note`). A steering note is the user's typed words, heard once at the next step, and only narrows: its addresses never count as known.
- Home (D-66, `src/main/home/`): one read-only query, `home()`, over the Logbook's sources, every word from main; Needs you is `needsYouEntries`, the Logbook's own view, so the two can't disagree, and deciding sends the same ids through the same channels.
- What left the Mac (D-31, `src/main/sent.ts`): `activeProvider(sent)` needs a `SentTag` saying why, so a new request path won't compile without one; searches and pages are recorded in `tools/web.ts` where they go out (Claude's own searches in `loop.ts`). Rows hold names and counts, never the text sent, and live and die with chats (`SqliteSentLog`, or `MemorySentLog` with Remember my chats off).
- Monthly limit (D-33, `shared/cap.ts`): `JobRunner` checks `overCap` before a job's first step, never in a prompt; explain warm-ups skip past it. User questions always go through.
- Repeating jobs (D-34, `shared/repeat.ts`): a series is a `scheduled` job with `repeat`; each due time adds a run (a job with `seriesId`) and moves the series on past now, so missed runs become one. Daily to weekly only, `LIMITS.series` at once, never two runs of a series together. A damaged `repeat` reads as none.
- Charts (D-35): `make_chart` names columns; `main/chart.ts` reads the chat's tables (`shared/table.ts`, kept in memory per chat) and works out every number, and writes the Mermaid itself with quoted, cleaned labels. The model gets the same numbers and is told to `calculate` anything derived.
- Usage meter (`src/main/usage.ts`): code calls `count(key)`, which does nothing until main plugs in a `UsageMeter` (counters, kind `usage`), so tests never need a database. Requests are counted in `providers/index.ts` (`metered`), searches and pages in `loop.ts`, questions in `ChatSession.run`, jobs in the runner. "Forget everything Otty knows" leaves usage alone, and habits never read it. Never show money without a dated price table.
- Health (`shared/health.ts`, `HealthBanner.tsx`) and try-asking chips (`shared/suggestions.ts`) are pure functions, tested without a Mac. A chip fills the box and never sends.
- Confirm cards (D-60): tools call `ctx.confirm(card)` with a card built in `main/cards.ts` (host as the tool reaches it, `unusual` decided there), and `ChatSession.askConfirm` leaves a `Receipt` on the answer however the card ends. Its buttons ignore the pointer until armed (`components/ConfirmCard.tsx`). Settings saves one key at a time through `settings:set`, checked by `SETTABLE` in `ipc/check.ts`; forgetting is behind a hold with counts from `settings:counts` (D-61). The message box is one component (`components/MessageBox.tsx`), and its words are kept per chat in main (`ChatSession.setDraft`; the preload drops a window's own echo) (D-62).
- Step cards (`src/main/act/`): the model proposes and the user clicks. `runStep` looks the action up in the chat on show, so the renderer can't ask for anything that isn't on the card. Anything from the model goes to `osascript` through argv, never into a script's text. Risk (`risk.ts`) and what `open` may reach (`open.ts`) are in code, and neither loosens without a test.
