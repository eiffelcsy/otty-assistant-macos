# Otty — notes for Claude

- Target is macOS, but development may happen on Windows. `npm run typecheck` and `npm run build` work anywhere. Capture, permissions and Reminders only work on macOS (`process.platform === 'darwin'` guards).
- Electron 45 has an **async, W3C-style clipboard API** (`clipboard.read/readText/write/writeText` return Promises, plus `ClipboardItem`). The old sync `readHTML`/`readImage` APIs are gone.
- Electron 45 no longer downloads its binary on install; the `postinstall: install-electron` script does it, so electron-vite can find `node_modules/electron/path.txt`. Don't remove it.
- The main process owns the conversation history (`ChatSession` in `src/main/llm.ts`). The renderer only receives `ChatEvent`s. The API key never reaches the renderer.
- Model services live behind `Provider` in `src/main/providers/`, with one adapter per API format (OpenAI's, Anthropic's), not per company. Code outside it never builds a request or checks which service it is. Claude-only request fields stay in `claudeExtras`, because other Anthropic-style servers could reject them. `Message` keeps OpenAI's shape, and adapters translate as they send, so saved chats never change. Features read the `Profile` (`providers/profiles.ts`). With `web: 'off'` nothing may leave the Mac, and a local model never gets the saved key.
- Chats are saved as threads through the `ChatStore` interface in `src/main/store/`, backed by SQLite (`otty.db`, `node:sqlite`, synchronous on main; text only, images stripped by `store/images.ts`). `ChatSession` writes the question on send and only the turn's rows at its end (`write(thread, from)`). The schema is in `store/db.ts`: once released, change it with a new migration, never by editing one. Old message shapes are read through `store/upgrade.ts`. Matching rules live in `src/shared/match.ts` (also used by find-in-chat, `lib/findInChat.ts`), ranking in `store/search.ts`, and every backend must pass `store/__tests__/search.contract.ts`. Reopening one emits a `load` event. Each capture carries the frontmost app (`frontmostApp()` in `capture.ts`) as `AppInfo`; a message has `captures[]` (rules in `src/shared/captures.ts`).
- DeepSeek's cache needs each request to repeat the last one byte for byte, so `systemPrompt` depends only on settings. Anything per-turn goes in `turnNote` (`language.ts`), at the end of the user message, and nothing already sent is rewritten. `llm.test.ts` guards this.
- Explain terms are markdown links `[term](#explain)`, tips are `> 💡` blockquotes, and proofread answers carry a ` ```fixed ` block. All are rendered in `src/renderer/src/panel/Markdown.tsx`. Keep `prompts.ts` in sync if you change a format. Explain cards are cached in main (`explainCache.ts`), never in a renderer. Background calls (explain cards, titles) use `complete()` with `reasoning: 'least'` and never touch `ChatSession` history.
- Web safety: answers never load remote images (`Markdown.tsx`), built pages have a CSP (`electron.vite.config.ts`, build only), and `read_page` asks first unless `knownUrls.ts` finds the exact address in what the user sent or a search or page returned. Never count the model's own text, and keep tool messages from echoing model input as addresses. Reading pages from the Mac (`pageReader.ts`) only opens public addresses and checks each redirect, and Claude's `web_fetch` stays off because it would skip these checks. Copied HTML (`copyFormats.ts`) drops pictures and unsafe links, because Word fetches them on paste.
- UX for non-technical users comes first: friendly copy, no raw errors, and confirm cards for side-effecting tools.
- CI (`.github/workflows/ci.yml`, macOS) runs `npm ci`, typecheck, `npm test` and build on every PR. Keep `package-lock.json` committed and in sync.
- Docs: requirements `docs/REQUIREMENTS.md` · plan, roadmap and smoke test `docs/DEVLOG.md` · shipped work `docs/CHANGELOG.md` · ideas `docs/BRAINSTORM.md`.
- Keep the docs moving: plan a feature as a DEVLOG entry before building it. When it ships, summarise it in CHANGELOG, delete the entry, add its smoke-test steps, and mark it `shipped` in BRAINSTORM. Add any feature or UX ideas you notice along the way to BRAINSTORM.
- Attachments (`src/main/files/`): the renderer only gets ids, names and thumbnails, never paths or file contents. Documents are read in a utility process (`fileWorker.js`, a second main entry in `electron.vite.config.ts`); `pdfjs-dist` and `mammoth` are runtime `dependencies` (externalized, loaded with `import()`), unlike everything else.
- Hotkeys (highlight / snip / whole screen) open the small **quick view** at the cursor (`src/renderer/src/quick/Quick.tsx`); the floating bubble opens the full panel. Both render the conversation from main's `ChatEvent`s through `useChat` (`lib/useChat.ts`), so ↵ "continue in chat" just swaps windows.
- UI work: `tools/ui-preview` (launch config `ui-preview`) renders the real views in a browser with a mock `window.otty`. Use `?view=panel|quick|pickup` and `&scene=chat|compose|empty|tray|settings|provider|page|proofread|history|find|onboarding` (for `pickup`: `reading|nowords|failed`) (`&home=none` hides the home-language features). Design tokens (colours, hairlines, elevation, radius scale) are at the top of `styles.css`. Reuse them instead of new hex values or borders.
- Pick up text: `tools/otty-ocr/` is a Swift helper (Apple Vision), run by `src/main/ocr.ts` with the picture on stdin. `npm run dev` and `build:mac` build it into `build/bin`, and electron-builder ships it from there. Keep Chinese first in its language list. `pickup/Pickup.tsx` lays invisible text over the picture and handles ⌘C and ⌘A itself.
- Otty is painted art: frames in `src/renderer/src/assets/otty/` are generated from `tools/otty-art/source/` by `tools/otty-art/prepare.py` (cut-out, crop, blink frame). Don't hand-edit the WebPs; add a source and rerun the script. `components/Otter.tsx` stacks the frames and CSS animates them.
- UI icons are Flaticon UIcons (rounded set) via `components/Icon.tsx` — no emoji in UI chrome. Colours are tokens at the top of `styles.css`.
- Idle budget (NFR-3): under 0.5% of a core, measured with `OTTY_METRICS=1` (`metrics.ts`). A smooth `infinite` animation on an always-visible window redraws all day and cost 1.6% on its own, so step it or run it briefly, and re-measure after changing what runs while idle. Hidden windows get `data-asleep`, which pauses their animations. Measure and run long test jobs under `caffeinate`, because a sleeping Mac stalls timers and fails tests that wait on them.
- Whole-screen capture uses `desktopCapturer`, which throws when Screen Recording is off, so it needs a `needs-screen` path. Otty's windows go invisible during it (`withWindowsHidden`).
- Services live in `src/shared/services.ts` (presets, privacy lines, `serviceAt`); `ConnectionFields.tsx` is the picker in Settings and onboarding. Keys are saved per service in `settings.ts`.
- The proofread card's marks come from `shared/diff.ts` comparing the highlighted text with the model's ` ```fixed ` block, never from the model.
- Every iteration ends with a docs pass: check README, REQUIREMENTS, DEVLOG (architecture, roadmap, status), CHANGELOG and BRAINSTORM against the code, and add any new ideas.
